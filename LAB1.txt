- heap에서는 왠만해선 move / stack에서는 왠만해선 copy 
ㄴ 무거운 heap에서는 포인터 move 방식 / 가볍고 싼 stack에서는 그대로 copy 

* shadowing 
: 처음 정의시 mut을 사용하지 않고 정의한 후에 let을 사용해서 변경하는 경우 허용 
--> let을 사용해서 변경한다는 거 자체가 의도한 변경으로 명시를 한 것이므로 허용
--> 단, 두번째 let 사용시 첫번째 let의 경우 out of binding에 따라 scope이 나가고 heap에서 사라지고 
두번째 let이 새로 heap에 자리를 잡게 되는 순이다.
--> python의 garbage collector와 다르게 최적화가 된 rust의 장점

ㄴ 문자열은 heap 메모리에 존재한채 slice만 heap의 위치 포인터로 스택에 존재
- &'static str : compile 타임에 str 타입이 결정된다는 표시
ㄴ 누가 소유자인지는 상관없이 어느 binary에는 살아있으니 그대로 사용해도 된다는 의미

* if문도 expression 가능 --> return 바로 가능 
ㄴ expression 될 때는 세미 콜론 x
ㄴ statement로 사용하고 싶을때는 세미 콜론 o
ㄴ 단, if문의 모든 브랜치 (else if, else)가 만드는 값은 동일한 타입의 값이 생성되어야 함

* match : 모든 케이스를 체크할 것을 강제하는 if문
ㄴ 예를 들면 if문 구조에서 else문이 없을 경우, 컴파일 자체가 안됨 
ㄴ match도 if문과 동작하는 것은 동일
ㄴ '_' wildcard : 나머지 모든 경우(else)에 대해서 처리할 때 사용

* for문 : C보다는 Python에 가까운 형태 
ㄴ for문은 ownership을 가져가는 구문.

ㄴ 그렇다고 제품 로그로써 쓸만한 정도는 아니다
